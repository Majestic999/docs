| **Description** | This project uses a sound sensor module to continuously monitor ambient noise levels. When the noise level exceeds a predefined threshold, a buzzer sounds an alarm to indicate excessive noise. |

## Mounting the component on the breadboard

**Step 1:** Mount the ESP32 board on the breadboard across the central dividing channel.

Insert the left-side pins into Column D (Rows 1 to 15) and the right-side pins into Column G (Rows 1 to 15).

Ensure the USB port faces outward towards the edge of the breadboard.

**Step 2:** Insert the Sound Sensor Module pins into separate rows on the breadboard.

Place the Analog Output pin (AO) in Row 20, Column J, the Ground pin (GND) in Row 21, Column J, and the Power pin (VCC) in Row 22, Column J.

Ensure that no two pins share the same row to avoid short-circuiting the module.

**Step 3:** Mount the buzzer onto the breadboard.

Insert the longer positive (+) leg into Row 30, Column J, and the shorter negative (−) leg into Row 32, Column J.

Ensure they are placed in different rows so the legs do not touch and cause a short circuit.

## Wiring Instructions

Follow these step-by-step connection instructions to wire the breadboard layout to the ESP32:

1. **Sound Sensor VCC Connection:** Connect a jumper wire from Row 22, Column I (Sound Sensor VCC pin) to the **5V** (or VIN) pin on the ESP32 board.

2. **Sound Sensor GND Connection:** Connect a jumper wire from Row 21, Column I (Sound Sensor GND pin) to a **GND** pin on the ESP32 board.

3. **Sound Sensor AO Connection:** Connect a jumper wire from Row 20, Column I (Sound Sensor AO pin) to **GPIO 36** (VP) on the ESP32 board.

4. **Buzzer Positive Connection:** Connect a jumper wire from Row 30, Column I (Buzzer Positive leg) to **GPIO 18** on the ESP32 board.

5. **Buzzer Negative Connection:** Connect a jumper wire from Row 32, Column I (Buzzer Negative leg) to a **GND** pin on the ESP32 board.

6.

Connect the ESP32 board to your computer using the Micro USB cable.

## PROGRAMMING

**Step 1:** Open your Arduino IDE. See how to set up here: [Getting Started](../../Getting Started/Arduino_IDE_Setup.md).

### 1. Variable Declarations

```cpp
int soundPin = 36;
int buzzerPin = 18;

int soundValue = 0;
int threshold = 600;
```
*Explanation:* This block defines the pin assignments and state variables. `soundPin` assigns the sound sensor's analog output to GPIO 36, while `buzzerPin` assigns the alarm buzzer to GPIO 18. The `soundValue` variable holds the latest raw sensor reading, and `threshold` sets the cutoff limit (600) above which the noise alarm will be triggered.

### 2. Setup Function

```cpp
void setup() {
  pinMode(buzzerPin, OUTPUT);
  Serial.begin(9600);
}
```
*Explanation:* The `setup()` function runs once when the board powers up. `pinMode(buzzerPin, OUTPUT)` sets GPIO 18 as an output pin to control the buzzer. `Serial.begin(9600)` initializes serial communication at 9600 baud rate so you can observe the real-time noise readings on the Serial Monitor.

### 3. Loop Function

```cpp
void loop() {
  soundValue = analogRead(soundPin);
  Serial.println(soundValue);

  if (soundValue > threshold) {
    tone(buzzerPin, 800, 500);
    delay(1000);
  }
  delay(50);
}
```
*Explanation:* The `loop()` function executes repeatedly. `analogRead(soundPin)` reads the analog voltage from the sound sensor module and stores it in `soundValue`. `Serial.println(soundValue)` outputs the raw reading to the Serial Monitor. The `if` statement checks whether `soundValue` exceeds `threshold`. If true, `tone(buzzerPin, 800, 500)` sounds an 800 Hz alarm on the buzzer for 500 milliseconds, followed by a 1-second delay. A brief 50 ms delay stabilizes the sampling rate during normal operation.

## OBSERVATION

When the surrounding environment is quiet:

- The buzzer remains off.

- The Serial Monitor displays lower sound values.

When a loud sound is detected (such as clapping, shouting, or tapping near the sensor):

- The sound value increases.

- The buzzer sounds an alarm.

- The Serial Monitor displays higher sound readings.

If the alarm triggers too easily or not easily enough, adjust the `threshold` value in the code.
